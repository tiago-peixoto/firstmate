### Scenario 6 - worker-facing Definition of done wording in each mode

$ bin/fm-brief.sh brief-direct-pr widget --mode direct-PR   (Definition of done excerpt)
  1:Delivery contract: mode=direct-PR
  4:When it is implemented and committed, push your branch and open a PR with `gh-axi`, then append `done: PR {url}` to the status file and stop.
  5:That `done: PR {url}` is accepted only when this copy's HEAD - your latest commit - is pushed to your PR branch; the check tests that commit, not merely that a branch moved.

$ bin/fm-brief.sh brief-local-only widget --mode local-only   (Definition of done excerpt)
  1:Delivery contract: mode=local-only
  3:The task is complete only when committed on your branch `fm/brief-local-only`. Do NOT push, do NOT open a PR, do NOT merge.
  4:A `done:` is accepted when the named head is on this project's shared local branch, not only on a detached copy; the check tests that head, not merely that a branch moved.
  6:When it is implemented and committed, append `done: ready in branch fm/brief-local-only` to the status file and stop.

$ bin/fm-brief.sh brief-no-mistakes widget --mode no-mistakes   (Definition of done excerpt)
  1:Delivery contract: mode=no-mistakes
  3:When you believe it is complete, append `done: {summary}` to the status file and stop.
  5:That first `done:` is the handoff that starts the pipeline, which owns the push; it is not a request to push from this copy.
  32:After /no-mistakes reports CI green (the CI-ready return point - do not wait for it to keep monitoring in the background until merge), append `done: PR {url} checks green` and stop. You are finished.
  33:That CI-ready `done:` is accepted only when this copy's HEAD - your latest commit - is one the /no-mistakes run pushed, so commit nothing after the run; the check tests that commit, not merely that a branch moved.
